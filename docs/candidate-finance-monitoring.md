# 候選人政治獻金摘要監測

候選人政治獻金以監察院政治獻金公開查閱平臺的候選人會計報告為準。網站只發布候選人層級的收入、支出與餘絀彙總，不下載進資料庫，也不發布捐贈者、支出對象、身分證字號、地址、電話或逐筆交易。

## 第一批範圍

- 選舉：2022 年直轄市長與縣市長選舉，涵蓋全部 22 個縣市。
- 申報版本：首次申報。
- 官方彙總：96 筆。
- 與本機中選會正式候選人以「姓名＋選舉」精確配對後，可發布 71 筆。
- 25 筆有政治獻金專戶但沒有精確命中正式候選人，不發布。
- 23 位正式候選人在這批首次申報彙總中沒有精確資料，保留為明確缺口，不補零也不推測。
- 模糊配對：0 筆。

這批歷史資料可呈現在 2026 候選人的人物頁，作為其 2022 參選紀錄的財務摘要；不得標示為 2026 年政治獻金。

## 本機執行

取得監察院候選人層級彙總：

```bash
npm run fetch:candidate-finance
```

先與完整本機 Supabase 比對，不寫資料：

```bash
npm run stage:candidate-finance
```

重新取得、比對並只套用到完整本機 Supabase：

```bash
npm run monitor:candidate-finance:local
```

測試來源限制、隱私邊界、配對與發布遷移：

```bash
npm run test:candidate-finance
```

下載與 staging 產物位於 `tmp/candidate-finance/`。經人工覆核的可重現快照位於 `data-sources/cy/2022-election/`。

## 審核與公開邊界

- 下載主機必須是 `ardata.cy.gov.tw`，並保留壓縮檔與彙總 CSV 的 SHA-256。
- 解析器只接受 `election_incomes and expenditures_first.csv`；逐筆收入與支出 CSV 不得解析。
- 姓名與選舉必須同時精確命中單一正式候選人；零命中或多重命中都留在 staging。
- 公開摘要必須綁定 `candidate_id` 與 `person_id`，並標記資料年度、選舉、申報版本、來源網址及觀察日期。
- 寫入命令拒絕非 loopback Supabase。正式 Supabase 仍須經獨立發布與核准流程。

## UI

人物頁既有的「政治獻金」區塊會顯示收入、支出、餘絀、資料來源與原始連結。若人物同時是 2026 候選人或現任者，摘要仍清楚標示為 2022 年對應選舉，不與 2026 參選狀態混合。

## 下一批建議

依相同規則擴充 2022 年直轄市議員與縣市議員候選人；先分縣市產生覆核快照，再決定是否發布，避免一次放大姓名同名與跨選舉配對風險。
