# 每日人物持續研究

每日批次依固定順序一次處理 25 位人物，目標是持續追蹤家族關係、黨籍異動與司法線索。批次不會直接寫入正式 Supabase，也不會自動公開敏感資料。

每位人物先執行一次不加日期限制的歷史補查；三類查詢都有成功結果後，滿 30 天冷卻期即可進入近期監測。30 天是最低冷卻期，不是固定只查 30 天：若因佇列延遲，查詢範圍會從上次三類皆成功的日期動態延長，並多保留一天重疊，避免漏掉等待期間。歷史補查「完成」只代表指定來源查詢成功，不代表能證明沒有其他歷史資料；Google News RSS 的排序與回傳範圍仍可能漏掉舊資料。

## 選取順序

1. 正副總統、立法委員與縣市首長。
2. 縣市議員。
3. 鄉鎮市長及其他人物。
4. 同一層級內，以近期選舉優先，再依現任、再次參選、歷史候選人排序。
5. 鄉鎮市民代表、區長與村里長統一排在後段，其中依序為現任、曾當選、多次參選未當選；僅參選一次且未當選者排在全部清單最後。

曾參選或任職的歷史人物會留在候選池中；目前擔任較高層級公職者依現職排序，不會因早年曾參選代表或里長而被降到基層區。

依既有決策，暫時排除：

- 第一次參選的 2026 候選人。
- 各縣市副首長與局處等行政單位首長。

每日名額同時有歷史補查與到期監測時，約一半保留給到期監測，其餘用於未處理或待重試的歷史補查；任一側不足時由另一側補滿。歷史補查若有任一類來源失敗，會保存失敗結果，冷卻 30 天後再試；三類都成功才記錄完成時間。近期監測也只有在三類都成功時才更新最後成功時間，失敗後的下一次查詢會繼續涵蓋尚未成功的整段期間。

生日、性別、學歷、一般經歷與外部 ID 不再列入每日搜尋；這些欄位改由最近一次已完成身分對應的中選會正式選舉公報補齊。較舊公報只補歷史選舉脈絡，不得壓過較新的公報；生日與性別僅比對、去重，真正衝突才進待審；公報政黨只代表該次選舉，不覆蓋後續黨籍異動。

每日 25 人只持續研究家族關係、黨籍異動與司法線索。司法裁判搜尋仍須先有案件線索並完成身分核對，不會只憑姓名掃描與合併。

Wikidata 身分配對不強制要求性別。姓名、政治／公職脈絡與職位、經歷、學歷、黨籍或地區等條件會逐項記錄；強證據候選可產生一般待審 claims，較弱候選則以 `identity_review_required` 保留 QID、命中條件數與衝突，交由後續程序判斷，仍無法判斷時才人工審核。

## 每日執行

完整每日唯讀／待審流程：

```bash
npm run monitor:daily
```

若任一步驟回報 `degraded`、`partial`、`failed` 或 `needsAttention: true`，流程仍會輸出完整摘要，但最後以非零狀態結束，讓排程器發出通知。

只執行每日 25 人持續研究：

```bash
npm run run:daily-person-enrichment
```

流程會在 `tmp/` 產生：

- `daily-person-enrichment-pool.json`：依優先級排序的候選池。
- `daily-person-enrichment-targets.json`：當日 25 人清單。
- `daily-person-research-queue.json`：記錄當批家族、黨籍與司法搜尋計畫、collectionMode 及日期範圍；不包含基本資料、一般經歷或歷屆政見。
- `daily-person-research-news.json`：逐一搜尋當日人物的家族、黨籍與司法新聞。首次補查不加日期限制；後續監測至少回看 30 天，若排隊或來源失敗則依上次三類皆成功時間延長；每人每類都有成功、無線索或來源錯誤狀態。
- `daily-person-enrichment-claims.json`：Wikidata 產生的家族與黨籍待審線索；不產生日、性別、學歷或一般經歷 claims。
- `daily-person-enrichment-skipped.json`：未形成 claims 的人物，以及待程序審核的 Wikidata 身分候選、證據條件與衝突。
- `daily-person-enrichment-state.json`：每人最近處理日期、30 天最低冷卻、歷史補查結果與完成時間、近期監測最後成功時間、上一批起訖人物及逐人結果。
- `daily-person-enrichment-progress.json`：本次 25 人的來源結果、claim 數與失敗原因。

這些都是本機工作檔，不納入 Git。蒐集排程負責執行搜尋，Codex 審核排程只審核既有產物，不會自行補搜。所有線索保留為本機待審；司法搜尋仍遵守下述線索與身分門檻。

## 歷屆政見

中選會歷屆選舉公報的政見匯入另作一次性資料專案，完成全面盤點與解析後再統一處理，不加入每日 25 人排程。

## 司法紀錄

近期重大司法事件由不限定姓名的每日新聞監測涵蓋；每日人物流程另以姓名搭配罪名與程序詞搜尋，首次形成跨年度線索，完成後至少回看最近 30 天；若實際輪到該人物的時間更晚，範圍會從上次三類皆成功的日期延長。結果寫入 `daily-person-research-news.json`。姓名與法律詞需在標題中形成短距離關聯，以排除明顯只是評論他人案件的結果；其餘較弱候選仍交由後續程序審核。

新聞線索經姓名、現任或曾任職位、罪名、事件年份與程序階段確認後，才搜尋司法院官方刑事裁判。既有開放 API 指令只檢查近期異動裁判，不等同歷史全文搜尋；可在服務時段且已設定帳密的環境執行：

```bash
npm run fetch:daily-person-legal-leads
```

司法資料只建立私人待審線索。姓名相同不代表同一人，仍須核對職位、地區、年份、罪名、程序、案號與新聞脈絡。

## 發布邊界

- 每日批次不搜尋或更新生日、性別、學歷、一般經歷與外部 ID。
- Wikidata 家族關係永遠不自動公開。
- 新聞與司法搜尋結果永遠不自動建立公開犯罪紀錄。
- 每日批次沒有正式資料庫寫入參數。
