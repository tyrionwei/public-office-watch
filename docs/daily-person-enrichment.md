# 每日人物資料補齊

每日批次一次處理 25 位人物，目標是逐步補齊公開履歷，並建立政治家族與司法紀錄的待審線索。批次不會直接寫入正式 Supabase，也不會自動公開敏感資料。

## 選取順序

1. 正副總統、立法委員與縣市首長。
2. 縣市議員。
3. 鄉鎮市長及其他人物。
4. 同一層級內，以近期選舉優先，再依現任、再次參選、歷史候選人排序。
5. 鄉鎮市民代表、區長與村里長統一排在後段，其中依序為現任、曾當選、多次參選未當選；僅參選一次且未當選者排在全部清單最後。

曾參選或任職的歷史人物會留在候選池中；目前擔任較高層級公職者依現職排序，不會因早年曾參選代表或里長而被降到基層區。

依既有決策，暫時排除：

- 第一次參選的 2026 候選人。
- 各縣市副首長與局處等行政單位首長。

尚未處理過的人會優先於冷卻期已結束的舊對象。人物處理後會進入 30 天冷卻；等所有尚未處理者輪過後，資料仍有缺漏的人才會再次進入清單。

## 每日執行

完整每日唯讀／待審流程：

```bash
npm run monitor:daily
```

只執行每日 25 人補齊：

```bash
npm run run:daily-person-enrichment
```

流程會在 `tmp/` 產生：

- `daily-person-enrichment-pool.json`：依優先級排序的候選池。
- `daily-person-enrichment-targets.json`：當日 25 人清單。
- `daily-person-enrichment-claims.json`：Wikidata 產生的待審履歷與家族線索。
- `daily-person-enrichment-state.json`：最近處理日期，用於輪替。

這些都是本機工作檔，不納入 Git。

## 司法紀錄

近期重大司法事件由每日新聞監測涵蓋。需要查司法院開放資料時，可在服務時段且已設定帳密的環境執行：

```bash
npm run fetch:daily-person-legal-leads
```

司法資料只建立私人待審線索。姓名相同不代表同一人，仍須核對職位、地區、年份、案號與新聞脈絡。

## 發布邊界

- 學歷、經歷與基本欄位仍依來源等級和身分分數進入既有審核流程。
- Wikidata 家族關係永遠不自動公開。
- 新聞與司法搜尋結果永遠不自動建立公開犯罪紀錄。
- 每日批次沒有正式資料庫寫入參數。
