## 缺欄位保護

首次稽核把來源未提供的欄位視為 `NULL` 或 `false`，因此誤判 2,512 筆既有候選需要更新。實際來源涵蓋如下：

- 2012 年沒有候選號次與票數。
- 2022、2024 年沒有候選號次、當選狀態、票數與得票率。
- 缺少欄位代表「來源沒有提供」，不能解讀為空值、零票或未當選。

稽核已改成只比較來源實際存在的欄位。修正後：

- 原先 2,512 筆「安全更新」全部改判為既有資料已一致。
- migration 028 的既有候選更新數為 0。
- 未清除任何既有號次、票數、得票率、當選結果或公開狀態。
- 另有回歸測試確保未來來源缺欄位時不會再產生清空更新。

## 候選 migration 028

修正缺欄位語意後，真正需要的操作只有建立 6,063 筆候選：

| 項目 | 數量 |
|---|---:|
| 建立候選 | 6,063 |
| 更新既有候選 | 0 |
| 有票數 | 3,809 |
| 有得票率 | 3,809 |
| 當選 | 4,247 |
| 缺少候選號次 | 26 |

26 筆缺號次來源集中於 2012 年；資料表允許 `candidate_no = NULL`，因此保留缺值，不猜測號碼。

安全建立條件：

1. 來源只有一位有效人物。
2. 年份、職位、歷史縣市、選區編號及原住民分類只對應一個 canonical race。
3. 該人物在該選區沒有候選紀錄。
4. 該人物在同一場選舉沒有落在其他選區的候選紀錄。
5. 同一人物／選區只有一筆中選會來源。

Local 驗證：

- dry-run 實際建立 6,063 筆後完整 `ROLLBACK`，候選總數維持 67,414、歷史候選維持 2,278。
- migration 028 套用後，`cec-historical-candidate-*` 由 2,278 增至 8,341。
- 8,341 筆歷史候選全部 `is_public = false`。
- migration 以單一交易重跑後仍為 8,341，沒有重複人物／選區候選。
- `published.candidates` 對這批歷史候選的筆數為 0。
