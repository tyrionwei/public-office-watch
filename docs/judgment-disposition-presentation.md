# 司法紀錄：逐人主文摘要契約

判決結果、罪名與刑度的摘要只使用**本次法院的主文，以及其中已核對歸屬於此人的部分**。
「本院判決如下」通常是引導文字；須辨認實際主文區段，不靠該固定字串判斷整份文件。
事實、犯罪事實、事實及理由、事實與理由、理由及理由摘要不參與結果分類或刑度擷取。
原文／來源保留供查核，這不是刪除文件或隱藏原判決。

## 邊界與人工核對

1. `extractJudgmentMainText()` 是無 I/O 的主文區段擷取輔助函式；只能產生**私人待核對輸入**。
   不識別人物、不自動核准、不把結果直接寫入公開 claim。
   支援分隔空白、全形空白、常見編號與 CRLF；無主文、重複主文或模糊段落邊界回傳 null。
2. 一份主文可包含多名被告。審核者必須逐人對應穩定的 person ID，保留該人的完整命令、
   個別刑度、應執行刑、緩刑、易科／易服條件及沒收等必要限定。不能只找到同名就合併，
   不能把另一被告的有罪／無罪或刑度併入。不得用案由、被訴罪名或理由中的前審敘述替代。
3. 主文僅載「上訴駁回」、發回、更審或引「如附表」時，不自行從理由推導有罪、刑度或定讞。
   附表僅能在它確為主文直接引用、且相關逐人主文欄已單獨核對後，作為新的待審來源；
   目前 helper 不自動讀表、讀 PDF 或擷取理由中的表格。未核對前維持結果待確認。
4. `有罪／無罪／mixed` 由審核後的逐人主文資料明確提供，不再從「存在刑度」或任意含
   「無罪」的 notes 推導。「被告主張無罪」不是法院宣告無罪；「不另為無罪」也不能僅靠
   關鍵字自動當成獨立無罪結果。案件是否定讞仍沿用另行核對的 caseStage，不能從刑期、
   判決日期、經過若干天、駁回上訴等字樣自動決定。

## 呈現欄位（本次新增，不是已完成資料遷移）

已通過既有敏感資料審核、身分核對與發布流程的 `claim_json`，可額外提供：

```json
{
  "recordType": "criminal",
  "caseStage": "criminal_judgment_non_final",
  "judgmentDisposition": {
    "version": 1,
    "section": "主文",
    "reviewStatus": "reviewed",
    "personId": "<公開查詢回傳的 canonical claim.person_id>",
    "sourceUrl": "https://<此筆 claim.source_url 的同一原始來源>",
    "text": "被告甲犯誣告罪，處有期徒刑參月。",
    "result": "guilty"
  }
}
```

以上是合成格式範例，不是任何真實人物資料。`text` 只能是已核對逐人主文原句，
不可是整份主文、整份判決、新聞敘述或「事實與理由」段落。`result` 可為 guilty、
acquitted、mixed 或 unknown；不得為了顯示摘要自動補 `reviewed` 或填入 guilty。

`PersonPage` 會傳入實際 `claim.person_id` 與 `claim.source_url`，呈現層要求與新欄位一致。
人物 ID 指 published 查詢回傳的 canonical person ID；已合併人物的資料表原始 claim.person_id 可能不同，不能直接沿用。後續人物合併造成不一致時，先維持待確認，重新核對後才更新逐人主文欄位。
這只是防誤配的格式／生命週期檢查，不是新增授權機制，不取代伺服器公開邊界或人工審核。
對不到人物、來源、段落或明確結果時，顯示原紀錄／主文及「結果待確認」，不自動猜。

## 舊資料相容行為

既有的簡短敘述目前不包含此欄位，將保留原文，不再由全文關鍵字產生有罪／mixed 與刑度摘要。
已核對的具體無罪 caseStage 保留；generic criminal_judgment 只代表判決階段，不等於有罪。
逐人主文若與具體無罪階段衝突，則停用摘要並維持結果待確認，交回審核。
主文原文在必要時直接顯示，原本 claim_value 仍保留於「展開完整紀錄」，不被覆寫。

本 patch **不**抓取、回填或發布既有資料；需要原判決的案例，由原本的本機研究／審核流程
逐筆建立資料，日期、人物、來源與最終公開核准仍走原流程。不要批次替所有舊敘述加 reviewStatus。

## 驗證與套用範圍

`node --experimental-strip-types --test apps/web/tests/legalRecordPresentation.test.ts`

涵蓋前審刑度／後審無罪、被告主張、主文與理由分隔、多被告隔離、人物及來源誤配、
附表／駁回／發回待確認、刑期附帶條件、metadata 衝突及舊資料原文保留。
原有正向刑度案例改成明確逐人主文 fixture；不是把任意歷史敘述當作主文來湊測試通過。

套用前後不需要 Docker、資料庫還原或全機盤點。這次不修改 WSL、worktree、排程、錢包、
migration、支持留言、政見投票或正式資料。仍需在完整專案執行相關 lint、型別／建置及人物頁
原文展開的瀏覽器驗證，純函式測試通過不代表這些整合測試已完成。
