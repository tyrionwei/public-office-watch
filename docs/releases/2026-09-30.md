## PR 優先的執行順序

本輪使用以下順序；正式 migration 或資料寫入不是建立 PR 的前提：

1. 建立審查用 Draft PR（release → main）。
2. 審查與修正，執行 PR CI；PR 準備階段到此停止，正式發布須完成第3步授權。
3. 另行確認正式發布範圍與授權。
4. 正式基準對齊、備份與演練。
5. migration／資料套用。
6. 最終 CI 確認、合併與部署，並完成部署後驗收。

`Web CI` 只在 pull_request 或 main push 執行，PR 使用 mock／離線測試且停用應用資料寫入 E2E；新增SQL回歸 workflow 僅在相關 PR 變更執行一次性合成資料庫測試。正式發布 workflow 未變更，僅接受 main 的成功 Web CI push，或 main 上明確手動觸發。資料同步 workflow 僅手動 dry-run。分支 push／PR 不會自動寫正式資料或部署。
