# 每週資料監測

每週流程用於做較廣範圍的來源刷新與資料品質盤點。它補足每日流程的短期新聞與 25 人補齊工作，但不會直接修改正式 Supabase，也不會自動公開候選人、黨籍、司法或人物資料。

## 每週檢查內容

1. 執行正式公開資料來源的完整唯讀預覽。
2. 檢查中選會是否出現 2026 候選人公告、下載檔或新頁面。
3. 比對中選會公投專區、投票結果及地方性公投頁面，找出新增或移除的官方公投連結。
4. 重新取得可自動存取的政黨候選人頁面：
   - 民進黨
   - 國民黨
   - 親民黨
   - 台灣前進聯盟收錄的政黨
5. 使用既有瀏覽器快照比對民眾黨資料。
6. 比對政黨來源快照與本機待審候選人資料。
7. 補查最近八天的重大新聞，避免每日流程暫停時漏失。
8. 檢查現任立委人數、候選狀態與人物資料品質。

## 執行

```bash
npm run monitor:weekly
```

報告預設寫入：

```text
tmp/weekly-monitor/
```

主要檔案包括：

- `summary.json`：各步驟成功或需注意的摘要。
- `logs/`：每個步驟的完整輸出，供失敗時追查。
- `cec-candidate-sources.json`：中選會候選人來源發現結果。
- `cec-referendum-sources.json`：中選會公投官方頁面的內容雜湊、新增連結與移除連結；首次執行只建立基線，不把歷史連結誤報為新增。
- `cec-referendum-snapshots/`：依內容雜湊保存的本機 HTML 快照，供人工比對。
- `party-candidates/`：本週政黨候選人來源快照。
- `party-candidate-freshness.json`：來源與本機待審資料差異。
- `weekly-person-news.json`：八天新聞補查結果；保留各來源線索，並將同一人物、類別、日期及事件詞整理為事件群組。
- `person-data-quality.json`：人物欄位與衝突盤點。

如需另存一份測試結果：

```bash
npm run monitor:weekly -- --output-dir tmp/weekly-monitor-preview
```

## 失敗處理

任一來源失敗時，流程仍會繼續檢查其他來源，最後以 `needs_attention` 結束，並在 `failedSteps` 列出失敗項目。這種狀態代表需要查看對應的 `logs/*.log`，不代表既有公開資料已損壞。

民眾黨網站目前有瀏覽器安全檢測，因此每週流程只比對已保存的瀏覽器快照，不聲稱已取得最新頁面。需要更新時，仍須由可正常開啟該網站的瀏覽器重新擷取。

## 發布邊界

- 所有新候選人、人物配對與狀態異動只形成待審結果。
- 新公投連結只形成本機待審線索；不自動新增公投、不寫正式 Supabase，也不自動公開題目或結果。
- 新聞只作為發現線索，仍須回到政黨、本人、主管機關或司法來源確認。
- 流程沒有正式資料庫寫入參數。
- Codex App 每週一 17:00 在原工作區執行此流程並保留本機產物。
- 只有蒐集失敗才通知；成功產物交由每日 21:30 審核排程處理。
